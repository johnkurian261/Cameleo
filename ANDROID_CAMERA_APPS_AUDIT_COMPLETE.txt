## 1. Executive Summary

This investigation delivers a deep, evidence-based reverse-engineering audit of three market-leading Android photography and creative camera applications: **VSCO**, **Prequel**, and **Adobe Lightroom Mobile**. 

The primary objective of this audit is to deconstruct their internal engineering paradigms—specifically analyzing their **camera capture architectures, live viewfinder preview pipelines, image processing flows, color science models, 3D LUT lookup implementations, optical lens distortions (such as fisheye and chromatic aberration), analog film simulations (grain, halation, and light leaks), GPU shader designs, and native acceleration engines**.

### Core Technological Findings Across the Triad:
1. **Camera API Dominance:** None of the three production applications rely on Android Jetpack's high-level `CameraX` library for their primary capture pipelines. All three implement direct **Camera2 API** (`android.hardware.camera2`) sensor controls to achieve low-level manual parameter adjustment (shutter speed, ISO, kelvin white balance, raw sensor capture, and manual focus distance).
2. **Color Science & 3D LUT Architecture:**
   - **VSCO** employs proprietary $17 \times 17 \times 17$ 3D ColorCubes packed into $17 \times 289$ 2D strip textures. Critically, VSCO applies a **1D inverse JPEG contrast curve** (`sRemoveJpegContrastTexture`) prior to color grading to linearize aggressive hardware ISP tone curves.
   - **Adobe Lightroom** standardizes on an $N \times N^2$ stacked 3D LUT architecture with bilinear sampling across vertical z-planes and linear interpolation between adjacent slices, combined with full Android 14+ **Ultra HDR (ISO 21496-1) gain map synthesis** and Sam Hocevar's branchless fast HSL transformations.
   - **Prequel** utilizes dynamic 2D color lookup tables and verifies output color matrix integrity through a native SSIM and 64-bin histogram protection library (`liblutprotector.so`).
3. **Optical Distortions & Lens Emulation:**
   - **Prequel** implements true radial fisheye lens distortion via `ACIFilterOpticalCompensation` and resolution-normalized transverse chromatic aberration via `AFPCITransverseChromaticAberrationEx`, scaling dispersion as a function of output viewport width relative to a 720p base coordinate space.
   - **VSCO** renders lateral chromatic aberration by shifting red and blue texture coordinates with mirrored border clamping to prevent edge artifacts.
   - **Lightroom** features an authentic, multi-element chromatic lens flare engine directly ported from Apple Metal (`vfLensFlareVideoEffectKernel`), generating 5 animated, 45-degree rotating dual-color chromatic flare circles.
4. **Analog Grain Systems:**
   - **Prequel** splits grain into two distinct pipelines: high-fidelity scanned optical halide grain plates (1.73 MB `grain.jpg`) blended via `CIOverlayBlendMode` for still photos, and golden-ratio procedural pseudo-random noise for video.
   - **VSCO** employs alpha-blended grain plates (`grain.png`) and multi-layer blend modes (Hard Light, Multiply, Screen).
   - **Lightroom** models grain parametrically via explicit XMP metadata (`GRAIN_AMOUNT`, `GRAIN_SIZE`, `GRAIN_ROUGHNESS`, `GRAIN_FREQUENCY`).
5. **Computational Photography & HDR:**
   - **Lightroom** leads with a native multi-frame RAW burst merge engine (`HdrCaptureWorker`), fusing bracketed raw frames natively in C++ via Adobe Camera Raw (ACR) demosaicing into 32-bit floating-point linear DNG negatives.
   - **VSCO** implements Local Laplacian Pyramid (LLP) tone mapping natively via `libfragglerock.so` for edge-preserving, halo-free clarity enhancement.

2. **Prequel Architecture:** Built around a declarative dataflow paradigm. Filter graphs are authored as JSON directed acyclic graphs (`main.batchfilter`) executed by an embedded JavaScript runtime (**LiquidJS**, `libliquidjs.so`). Computer vision and verification tasks route to OpenCV 4 and Alibaba MNN.
3. **Adobe Lightroom Architecture:** Built as an enterprise-grade mobile port of Adobe's desktop imaging engine. Capture is handled by `com.adobe.capturemodule.CaptureActivity` interfacing via JNI with `libcapture.so` (internal codename `Barry`). Post-processing, raw demosaicing, and tone curves are powered by `libimaging.so` (51.8 MB C++ binary containing the complete Adobe Camera Raw engine) and `libkernel.so`. Lightroom also integrates C2PA cryptographic provenance signing (`libadobe_c2pa.so`).

## 7. Preview Pipeline

For live viewfinder preview, all three apps stream camera frames through an OpenGL ES pipeline via `SurfaceTexture` and `GL_TEXTURE_EXTERNAL_OES`:
- **VSCO:** Incoming frames pass through `colorcube_ext_es2.glsl`. The shader samples `samplerExternalOES sImageTexture`, stripping JPEG contrast via `sRemoveJpegContrastTexture` and applying 3D ColorCube lookup at 60 FPS.
- **Prequel:** Streams external OES textures into its LiquidJS filter graph, allowing real-time preview of lens compensation, distortions, and procedural noise.
- **Lightroom:** Renders real-time live histograms, zebra clipping overlays, focus peaking highlights, and $N \times N^2$ 3D LUT simulations (`fragment_shader_lut_es2.glsl`).

## 8. Photo Processing Pipeline

Processing takes place predominantly on the **GPU** (via OpenGL ES 2.0 / 3.0 shaders) and in **native C/C++ libraries**:

- **Lightroom:** Desktop-grade C++ pipeline (`libimaging.so`). Handles 32-bit floating-point raw processing, bilateral demosaicing, PV2012 exposure controls, tone curve splines, and ISO 21496-1 Ultra HDR gain map export.

## 10. LUT / Hald / CLUT Analysis

### VSCO $17 \times 17 \times 17$ ColorCube Slicing
VSCO avoids heavy 3D texture uploads by flattening a $17 \times 17 \times 17$ RGB lattice into a 2D strip texture of dimension $17 \times 289$ (Width = 17, Height = $17 \times 17$):
- **Horizontal coordinate:** $x = \text{red} / 16.0$
- **Vertical coordinate:** $y = (\text{green} + \text{blue} \times 17.0) / 288.0$
- **Interpolation:** The shader fetches 8 corner texels (`p000` through `p111`) and performs 7 sequential linear interpolations (`mix`).

### Lightroom $N \times N^2$ Stacked 3D LUT
Lightroom stacks $N$ horizontal planes vertically. Red selects the vertical z-plane index, green indexes rows within the plane, and blue samples horizontal columns. Trilinear interpolation is achieved by sampling bilinearly from the lower and upper planes and linearly blending between them.

## 11. Color Science

- **JPEG Pre-Linearization (VSCO):** Recognizes that Android hardware ISPs bake aggressive S-curves into JPEG preview frames. VSCO feeds incoming frames through `remove_jpeg_contrast()` via a 1D lookup table (`sRemoveJpegContrastTexture`) before applying film LUTs.
- **Ultra HDR & Wide Gamut (Lightroom):** Full support for BT.2020, Display P3, and sRGB. Converts scene-linear BT.2020 into CIE XYZ, applies HLG system gamma ($\gamma_{\text{HLG}} = 1.2 + 0.42 \log_{10}(Peak / 1000)$), maps to sRGB BT.709, and generates log2 gain maps matching ISO 21496-1.
- **Branchless HSL Conversion (Lightroom):** Employs Sam Hocevar’s branchless RGB $\leftrightarrow$ HSL algorithms (`rgbToHcv`, `rgbToHsl`, `hueToRgb`) in GLES2 shaders.

## 14. Optical Effects

### Chromatic Aberration
- **Prequel:** Utilizes `AFPCITransverseChromaticAberrationEx`. The dispersion offset is dynamically normalized across resolutions:
  $$\text{aberrationValue} = 10.0 \times \left(\frac{\text{width}}{720.0}\right) \times \text{strength}$$
- **VSCO:** Shifter kernel in `es3_shader_fragment_chroma_aberration.glsl`. Displaces red by $+uStrength$, leaves green unchanged, and shifts blue by $-uStrength$ using mirrored coordinates (`mirrorCoord`) to eliminate border edge clamp artifacts.

## 15. Lens Effects

### Fisheye Lens Distortion (Prequel)
Implemented via `ACIFilterOpticalCompensation` inside `effect-adj-Fisheye/main.batchfilter`. Driven by dynamic parameter `useControls_adj_fisheye_ARGT`. It applies radial geometric curvature mapping simulating ultra-wide fisheye barrel distortion.

### Multi-Element Cinematic Lens Flare (Lightroom)
Implemented in `res/raw/vf_video_effect_lens_flare.glsl`, explicitly ported from Apple Metal (`vfLensFlareVideoEffectKernel`). It computes 5 rotating chromatic flare circles with 45-degree angle increments, splitting circles into warm cores (`0.9, 0.9, 0.1`) and cool anamorphic blue fringes (`0.1, 0.1, 0.9`).

## 21. Performance Architecture

- **OES Zero-Copy Viewfinder:** All three applications route live camera frames via `GL_TEXTURE_EXTERNAL_OES`, keeping frame data in GPU memory and bypassing CPU bottlenecks.
- **Asynchronous Capture Threads:** Dedicated background threads (`ImageReaderThread`, `HdrCaptureWorker`) isolate capture I/O from UI execution.
- **Memory Buffer Pooling:** Buffer reuse across native layers prevents memory churn and garbage collection pauses during burst capture.

### Trilinear Sampling GLSL Algorithm (`colorcube_ext_es2.glsl`)
The shader performs full 3D trilinear interpolation directly on the mobile GPU across 8 spatial corner vertices (`p000` through `p111`) using 7 sequential `mix()` (lerp) operations:

```glsl
// Extracted verbatim from res/raw/colorcube_ext_es2.glsl
#extension GL_OES_EGL_image_external : require
precision mediump float;

const float kIntensityFactor = 1.0;
const float kXrayDimension = 17.0;
const float kSubDimension = 16.0;
const float kXraySize = kXrayDimension * kXrayDimension; // 289.0

vec2 colorCubeTextureCoordinate(in vec3 rgbIndex) {
    return vec2(rgbIndex.r / kSubDimension,
                (rgbIndex.g + rgbIndex.b * kXrayDimension) / (kXraySize - 1.0));
}

vec4 lerp(in vec4 value1, in vec4 value2, in float diff) {
    return (mix(value1, value2, diff));
}

vec4 colorLookup(in vec3 rgb, in sampler2D colorCube) {
    vec3 floorRGBindex = vec3(floor(rgb.r * kSubDimension),
                              floor(rgb.y * kSubDimension),
                              floor(rgb.b * kSubDimension));

    vec4 p000 = texture2D(colorCube, colorCubeTextureCoordinate(floorRGBindex));
    vec4 p001 = texture2D(colorCube, colorCubeTextureCoordinate(vec3(floorRGBindex.r, floorRGBindex.g, floorRGBindex.b + 1.0)));
    vec4 p010 = texture2D(colorCube, colorCubeTextureCoordinate(vec3(floorRGBindex.r, floorRGBindex.g + 1.0, floorRGBindex.b)));
    vec4 p011 = texture2D(colorCube, colorCubeTextureCoordinate(vec3(floorRGBindex.r, floorRGBindex.g + 1.0, floorRGBindex.b + 1.0)));
    vec4 p100 = texture2D(colorCube, colorCubeTextureCoordinate(vec3(floorRGBindex.r + 1.0, floorRGBindex.g, floorRGBindex.b)));
    vec4 p101 = texture2D(colorCube, colorCubeTextureCoordinate(vec3(floorRGBindex.r + 1.0, floorRGBindex.g, floorRGBindex.b + 1.0)));
    vec4 p110 = texture2D(colorCube, colorCubeTextureCoordinate(vec3(floorRGBindex.r + 1.0, floorRGBindex.g + 1.0, floorRGBindex.b)));
    vec4 p111 = texture2D(colorCube, colorCubeTextureCoordinate(vec3(floorRGBindex.r + 1.0, floorRGBindex.g + 1.0, floorRGBindex.b + 1.0)));

    float xDiff = (rgb.r - (floorRGBindex.x / kSubDimension)) * kSubDimension;
    float yDiff = (rgb.g - (floorRGBindex.y / kSubDimension)) * kSubDimension;
    float zDiff = (rgb.b - (floorRGBindex.z / kSubDimension)) * kSubDimension;

    vec4 c00 = lerp(p000, p100, xDiff);
    vec4 c10 = lerp(p010, p110, xDiff);
    vec4 c01 = lerp(p001, p101, xDiff);
    vec4 c11 = lerp(p011, p111, xDiff);

    vec4 c0 = lerp(c00, c10, yDiff);
    vec4 c1 = lerp(c01, c11, yDiff);

    return lerp(c0, c1, zDiff);
}
```
